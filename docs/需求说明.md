# RaidWish 许愿助手 — 需求说明

- 作者：迪恩温彻斯特、秋枫
- 版本：1.0.0
- 适用客户端：《魔兽世界》："无限"（与正式服 12.x 共用插件接口）

本文是 RaidWish 的行为准则。以后改功能、修 bug、判断"这算不算 bug"，都以本文为准。代码与本文不一致时，先确认哪边对，再改另一边。


---

## 1. 概述

团队活动里用的许愿、分数、掉落记录与拍卖工具：

- **许愿**：团员在团队频道发 `xy` 加物品链接，许愿团长那边自动录入，全团同步可见。
- **分数**：每人一个分数，团长可以加减，掉落时可按出分自动扣分。
- **掉落记录**：记录谁拿到了什么，命中许愿的自动标记完成。
- **拍卖**：同一件装备多人想要时，在团队频道出分、同分 Roll 点，结果全团同步。

## 2. 角色

| 角色 | 说明 |
|---|---|
| 许愿团长 | 点了"开始许愿"的团长或助理。只有他的客户端录入许愿、改分数、判定掉落，再同步给全团 |
| 团长、助理 | 可以开始许愿、发起拍卖、主持拍卖（数秒、直接 Roll、取消） |
| 团员 | 看到同步来的许愿表和掉落列表；出分、Roll 点；只能看，不能改 |

界面上团长端和团员端看到的控件不同：团长专用的控件在团员端不出现，而不是置灰。

## 3. 许愿

### 3.1 录入规则

许愿进行中，许愿团长的客户端读取团队频道（团队、团队领袖），按下面规则录入：

| 消息 | 含义 |
|---|---|
| `xy` 开头（不分大小写，可以不带空格） | 发言者本人许愿 |
| `txy 名 姓 物品` | 代别人许愿；被代的人必须在团里。名字两段都写最稳；只写名、且团里只有一个人叫这个名时也能认出 |
| 只含物品链接（"仅 xy 模式"关闭时） | 视为发言者许愿 |

内容规则：

- 只允许物品链接和 `[物品名]`，可以用空白隔开，至少要有一件。
- 夹杂其他文字的，判为无效，原许愿保持不变。
- `xy 地板` 或 `xy [地板]` 是"地板"许愿（愿意要任何没人要的东西）。
- 手打的物品名可以放在括号里：`xy [墓碑节杖]`（半角 `[ ]` 和中文输入法的全角 `【】`、`［］` 都可以）。带括号的名字和装备链接一样参与自动处理：要和装备的正式名称完全一致才对得上。
- 也可以不带括号直接写文字：`xy 墓碑`（可以是简称；多件用空格或"、"分隔）。这种许愿照常记录、同步、参与"重复许愿"提醒，但**不参与自动处理**：拍卖时不自动出 5 分、不显示"你许愿了这件装备"、拾取时不自动扣分、不自动标记完成，由团长人工处理。`xy` 后面必须有空格（`xyz 哈哈` 不算），文字和链接或括号混在一起（`xy 我要这个 [物品]`）仍然无效。
- 代许愿不带括号时，前两个词是名字（名 姓），后面是物品：`txy 张三 李四 墓碑`。
- 同一件物品重复写只算一次；物品链接在前，手打名字在后。
- 每人最多许愿件数由设置决定（"设置 → 许愿规则 → 每人最多许愿件数"，默认 1，填 0 表示不限）。一条许愿超过件数时只记前几件（先物品链接、后手打名字，"地板"也算一件）。新的许愿整个替换旧的许愿。
- 只给当前在团的成员录入。

录入成功后，团长端那一行高亮闪一下；团员本人收到"你的许愿已记录：…"。

### 3.2 物品匹配

- 两边都有物品编号时比编号。
- 否则比名字：去掉颜色码、中括号、空白，转小写后完全相同才算同一件。名字互相包含（如"梦境碎片"与"公式：永恒梦境碎片"）不算。

### 3.3 通报

| 时机 | 发送者 | 频道 | 文案 |
|---|---|---|---|
| 开始许愿 | 许愿团长 | 团队 | 开团公告（可在设置里改，逐行发送） |
| 停止许愿 | 许愿团长 | 团队 | `许愿已截止，之后的许愿不再记录` |
| 让出许愿团长 | 许愿团长 | 团队 | `许愿团长已让出，团长或助理点"开始许愿"即可接手` |
| 同一物品 2 人及以上许愿（开启"许愿重复警报"时） | 许愿团长 | 团队 | `注意：物品名 已有 N 人许愿` |
| 团队频道出现物品链接或物品名（开启"许愿自动查询"时，不限许愿阶段） | 许愿团长 | 团队 | `「物品名」有 N 人许愿：甲（4分）、乙（3分）`（团员端不发通报） |
| 通报未许愿名单 | 团长 | 团队 | `还没许愿的有：甲、乙，请尽快许愿` / `全员都已许愿` |
| 播报全部许愿（每 0.5 秒一条） | 团长 | 团队 | `开始播报许愿（按角色名从低到高）：`、`【许愿】名字（职业）：许愿，N 分`、`许愿播报完毕。` |
| 发团队宣言 | 团长 | 团队通知 | 第一行加 `【宣言】`，逐行发送 |
| 密语 `cxxy` 查询 | 被密语的人 | 团队 | `名字 的许愿：…，现有 N 分` |

通报里的物品名是去掉空白、转小写后的形式。没有权限发团队通知时自动改发团队频道；超过 255 字节的消息自动拆成几条。

### 3.4 分数

- 新成员的分数是"默认分数"（默认 4，设置里可改）。
- 加分：`名字 加 N 分，现有 M 分`；扣分：`名字 扣 N 分，现有 M 分`。
- 设置全团初始分数：只改当前在团的成员，通报 `全团分数已重置为每人 N 分`，然后同步全量。

### 3.5 完成标记

- 每件许愿物品单独记"已完成"。完成的物品在列表里变淡、加删除线，不再计入许愿人数。
- 手动标记完成：整条许愿全部标为完成，通报 `名字 的许愿标记为完成（手动），现有 N 分`。可以撤销（只在本次登录内），撤销时通报 `已撤销 名字 的完成标记，许愿恢复为：…`。

## 4. 同步与团长选举

- 只有许愿团长的数据是权威的，团员端只读。
- 每次"开始许愿"，任期号为已知最大值 + 1。
- 团员只接受**团长或助理**、且**任期号不小于当前值**的宣告。
- 任期号相同时：真实团长优先，其次名字字典序小的，全团结论一致。
- 自己是许愿团长时收到更高任期的宣告，立即让位并提示"许愿团长已由 X 接任，你已转为团员模式"。
- 许愿团长离队：全团清空团长认定，提示"许愿团长已离队，可由团长或助理重新开始许愿"。
- 进团（或小队转团、登录时已在团里）自动请求全量，5 秒内没开始收到就重试，最多 3 次。
- 全量同步先进临时表，收齐并且条数对上才替换；超时或条数不对就丢弃并重新请求，正式表不变。
- 只在团队中通讯，五人小队不通讯。
- **修订号**：许愿团长每改一次数据（许愿、分数、掉落），修订号加 1，随宣告和同步消息发出。团员只接受不比自己手里旧的全量；收到更旧的（例如团长游戏崩溃后用旧存档重登），或者收到任期号落后的宣告，就提醒团长（全团只由一个人提醒）。团长端先暂停发全量，弹出一次选择："用团员的数据恢复"（直接采用，并在团队频道请大家用 `/xy` 核对自己的许愿和分数）或"保留我的数据（会覆盖团员的）"。这个弹窗不能按 Esc 关掉。

## 5. 掉落记录与自动扣分

### 5.1 记录

- 读取拾取消息（用客户端的格式串匹配，不写死中文）。
- 只记录设置里勾选的品质（默认橙、紫）；白色包含灰色。
- 同一人同一物品 10 秒内只记一次。
- 许愿团长负责记录并同步；团员只上报自己拾取的物品；团里没有许愿团长时各自本地记录。
- 清空许愿表时一并清空掉落列表。

### 5.2 许愿完成

拾取了自己许愿的物品时，该物品标记完成；开启"许愿自动查询"时通报 `名字 拿到了许愿的装备，还剩 N 分`。

### 5.3 自动扣分

开启"自动扣分"时，拾取装备的人按下面两种来源扣分（只在许愿团长端执行）：

1. **拍卖结果优先**：这个人在 3 小时内的拍卖里赢下了这件装备、还没扣过分，就按拍卖出的分扣，不限拾取时间、不看品质设置，通报前面加"拍卖结算："。直接全团 Roll 赢的不扣分。扣过的拍卖结果记为已扣，这条掉落也直接记为已拍。
2. **团队频道出分**：没有拍卖结果时，拾取者在拾取前 60 秒内在团队频道发过 0~9 的数字，且物品品质在"紫色 / 蓝色 / 绿色装备自动扣分"的勾选范围内（橙色不参与）。

两种来源都按下表扣：

| 出分 | 许愿状态 | 处理 | 文案 |
|---|---|---|---|
| 任意 N | 整条许愿已全部完成 | 扣 N | `名字 扣 N 分，还剩 M 分` |
| 任意 | 没有许愿 | 不处理 | — |
| 0 | 拾取物命中许愿 | 不扣，标记完成 | `名字 拿到了许愿的装备，还剩 M 分` |
| 0 | 未命中 | 不扣 | `名字 出 0 分，不扣分，还剩 M 分` |
| 1~4 | 有许愿 | 扣 N（命中许愿的再按 5.2 标记完成） | `名字 扣 N 分，还剩 M 分` |
| 5 | 命中许愿 | 不扣，标记完成 | `名字 拿到了许愿的装备（出 5 分，不扣分），还剩 M 分` |
| 5 | 未命中 | 扣 5 | `名字 出了 5 分但这件不是许愿的装备，扣 5 分，还剩 M 分` |
| 6~9 | 有许愿 | 扣 N−5，命中的标记完成 | `名字 拿到了许愿的装备，另扣 K 分，还剩 M 分` |

处理后清除此人的出分记录。

## 6. 拍卖

### 6.1 流程

**许愿截止后才能开拍**：许愿还在进行中时不能开拍或直接全团 Roll，否则开拍后才许愿的人也能拿到许愿加分。许愿团长点开拍时会弹窗"截止许愿并开拍"，确定后先截止许愿再开拍；其他团长、助理会被提示先让许愿团长停止许愿。

| 阶段 | 时长 | 说明 |
|---|---|---|
| 出分 | 10 秒 | 团员在团队频道发 1~9 出分，发 0 / P 放弃。能改变结果的出分（不低于当前最高分）或最高分的人放弃，才重新计时；比最高分低的出分照样记下，但不打断倒数 |
| 倒数 | 第 7 秒起 | 拍卖方在团队频道依次发 `3…`、`2…`、`1…`（带"…"是为了不被当成出分），1 秒后在团队通知发 `出分截止！` |
| 等待 | 1 秒 | 然后结算 |
| Roll | 10 秒 | 最高分有 2 人及以上时进入。名单内每人只认第一次 Roll（1-100），出分阶段提前 Roll 的也算；名单外的人 Roll 不算。时长固定，有人 Roll 不重新计时；同分的人都 Roll 完就立即结算，否则最后 3 秒倒数、时间到按已有的点数结算。直接全团 Roll 也是固定 10 秒 |
| 结算展示 | 3 秒 | 显示结果后自动关闭 |

### 6.2 出分校验

拍卖方校验，不合格的在团队频道警告，不记录：

- 出 5 分及以上：当前装备必须是此人的许愿装备，否则 `注意：名字 没有许愿这件装备，出的 N 分不算`；出分不能超过分数 + 5，否则 `注意：名字 只有 M 分，加上许愿的 5 分最多出 M+5 分，不够出 N 分`。
- 出 4 分及以下：不能超过分数，否则 `注意：名字 只剩 M 分，不够出 N 分`。

弹窗的出分按钮在本地先检查：已有更高出分 → `没出成：已经有人出了更高的分。`；分数不够 → `分数不够`；5 分及以上（许愿加分）要求是自己的许愿装备，并且自己的分数 + 5 够出。

弹窗的出分按钮分两排：第一排 1、2、3、4 分，所有人都有；第二排 6、7、8、9 分是许愿加分，只有许愿了这件装备的人才显示。5 分由插件在开拍 1 秒后替许愿的人自动出。

开拍 1 秒后，许愿了这件装备的人自动在团队频道出 5 分。

### 6.3 通报（拍卖方发送，团队通知频道）

| 时机 | 文案 |
|---|---|
| 开拍 | `开拍：[物品]，请在团队频道出分` |
| 直接全团 Roll | `全团 Roll：[物品]，需要的请 /roll` |
| 同分进入 Roll | `同分，请 甲、乙 /roll 决定归属` |
| Roll 再次同点 | `Roll 点相同，请 甲、乙 再 /roll 一次` |
| 出分胜出 | `甲 以三分拍得 [物品]，拾取时自动扣分` |
| Roll 胜出 | `甲 以 Roll 点 87 拿到 [物品]，出价三分，拾取时自动扣分`（直接全团 Roll 时只有 `甲 以 Roll 点 87 拿到 [物品]`） |
| 无人出分 | `[物品] 没人出分，流拍` |
| 无人 Roll | `[物品] 没人 Roll，流拍` |
| 取消 | `本次拍卖已取消：[物品]` |

分数用中文数字（零、一……九十九）。

### 6.4 其他规则

- 同分时一律进入 Roll：同分的人在拍卖弹窗里看到"Roll"按钮，点一下即 `/roll 1-100`，点数高的赢；其他人只能看。
- 同一时间只有一场拍卖。发起者是团长或助理；数秒、直接 Roll、取消只有发起者能用。
- 出分阶段点"直接 Roll"：放弃当前出分，对同一件装备改为全团 Roll。
- **待拍物品**：掉落记录里未拍的（许愿者拾取了自己许愿的物品除外），加上团队频道出现过的物品链接（最多 20 条、10 分钟；插件自己的拍卖和许愿通报不算）。按物品编号去重。待拍列表只收设置里勾选的品质。
- 手动加入待拍：把物品拖到掉落列表上，或打开掉落页时 Shift 点击聊天框里的物品链接。
- **"不要这件"**：弹窗收成小条，并记住这件装备；以后再拍它时弹窗默认收起；自己出分或进入 Roll 阶段时清除记号并展开。
- 结算结果写入掉落列表（赢家与分数或 Roll 点），并保留最近 20 条结算记录供拾取分配使用。
- `/xypm`：拍最早的一件待拍物品。

### 6.5 语音

开关在"设置 → 拍卖 → 语音播报"，默认关。同一秒内最多播一个。插件自带的默认语音是合成语音，文件在 `addon/RaidWish/voice/`。

**真人语音包**：真人录音不进仓库（仓库里只有合成语音），打发布包时才放进去。
- 发布包只有一个文件夹 `RaidWish`，真人语音在里面的 `voicepack/` 子文件夹；玩家只装一个插件，上传插件平台也只传一个包。
- 有语音包时，"设置 → 拍卖"里多一项"使用语音包「名称」，录音：某某"（默认开）。开着时优先播语音包里的同名文件，语音包里没有的句子自动用默认语音。
- 语音包在加载时登记全局表 `RaidWishVoicePack = { path, name, author, version, license }`（发布包的 TOC 里多一行 `voicepack\VoicePack.lua`）。
- 语音包不适用 MIT 许可证，`voicepack/VOICE_LICENSE.txt` 写明：仅限配合 RaidWish 使用，禁止提取、修改、从插件里拆出来单独发布，禁止用于 AI 训练或声音克隆；连同插件原样转发是允许的。发布包的 `LICENSE.txt` 末尾也注明这一点。
- 打包：`python -X utf8 tools/release.py --voice recordings --voice-name 名称 --voice-author 录音者`，输出 `dist/RaidWish-版本.zip`；不带 `--voice` 就是只有合成语音的版本。打完用 `tools/sim/release_check.lua` 检查能否加载。
- 录音放在 `recordings/`（已被 .gitignore 忽略），按 `docs/录音稿.txt` 的文件名命名。处理方式默认 `enhance`：剪掉首尾静音、去掉 70Hz 以下的低频、轻度压缩、按听感响度把各句调到一样响并防爆音；不降噪、不变调、不加混响。`--mode basic` 只剪静音和调音量，`--mode raw` 只转格式。
- 也可以用 `tools/voice/make_pack.py` 做成单独的插件 `RaidWish_Voice`（私下发给个别人时用），登记的是同一个全局表。

| 文件 | 时机 | 内容 |
|---|---|---|
| auction_start | 开拍 | 拍卖开始 |
| my_wish | 开拍，是自己许愿的装备 | 你许愿的装备来了 |
| bid_1 ~ bid_4 | 点 1~4 分按钮 | 出一分 …… 出四分 |
| bid_6 ~ bid_9 | 点 6~9 分按钮（许愿加分） | 许愿出六分 …… 许愿出九分 |
| bid_5_auto | 自动出 5 分 | 许愿自动出五分 |
| bid_fail | 出分失败、重复 Roll | 不行哦 |
| collapse | 收起弹窗、不要这件 | 已收起 |
| countdown | 开始倒数 | 倒计时三秒 |
| outbid | 自己的出分被超过 | 有人出了更高的分 |
| roll_start | 进入 Roll 阶段 | 同分了，开始掷点 |
| outrolled | 自己的 Roll 被超过 | 你的点数被超过了 |
| won_bid | 自己出分胜出 | 恭喜你，拍到了 |
| won_roll | 自己 Roll 胜出 | 恭喜你，掷点赢了 |
| auction_end | 别人胜出或流拍 | 拍卖结束 |
| all_sold | 最后一件拍完（拍卖方，延迟 3 秒） | 全部装备都拍完了 |

## 7. 拾取分配

**待定**（等团本里的拾取探测结果）。候选人的计算已确定：自己、指定拾取人、随机、许愿了该物品的人、"地板"许愿的人、该物品的拍卖赢家（最早一次结算优先，分配后移除该条记录）、按职业分组；紫色及以上或设置了"总是询问"时分配前二次确认。

## 8. 数据安全

- **快照**：许愿表变化 2 秒后、以及正常退出时自动保存（"自动快照"开关，默认开）；许愿表为空时不覆盖已有快照。
- **登录检查**：先清理 24 小时前的许愿和掉落记录；然后如果没有任何人许愿，而 12 小时内的快照有 3 条以上，就弹窗询问是否恢复，主窗口右下角显示"发现未恢复的数据 · 恢复"。快照之后主动清空过许愿表的不提示。
- **从团员恢复**：本地没有任何许愿时点"开始许愿"，先询问团员；只让一个人回全量（助理优先，其次名字字典序最小）；团长确认 `来自 X 的 N 条许愿记录，是否采用？` 后才采用，然后继续开始许愿。确认之前不会开始，不会把空表同步给全团。
- **游戏崩溃**：客户端只在正常退出、重载界面时写存档，崩溃时本机这次的改动会丢。但团员内存里有完整副本：
  - 许愿团长崩溃后重登，如果本地一条许愿都没有，点"开始许愿"会先问团员（确认 `来自 X 的 N 条许愿记录，是否采用？` 后采用）；如果本地是旧数据，团员会按第 4 节的修订号规则提醒团长，团长选"用团员的数据恢复"即可。两种情况都不会把旧数据同步给全团。
  - 团员崩溃后重登，自动向团长要全量。
  - 全团同时掉线（例如服务器断线）时，只能恢复到最后一次写盘的状态。首领战之间 `/reload` 一次，或导出一份备份码，可以缩小损失。
- **状态行**：许愿团长自己的名字后面有个小标签按钮"让出"，点后在确认框里再点红色的"让出"。
- **清空入口**：许愿页底部右侧有红色小按钮"清空许愿表"（团长端），设置 → 数据 里也有；都要再确认。清空的范围是所有人的许愿和分数、掉落记录、待拍列表、拍卖结果和"不要这件"标记，许愿团长清空时全团一起清空；正在进行的拍卖会被取消。许愿还在进行中时不能直接清空：许愿团长的确认按钮变成"停止许愿并清空"，其他人会被提示先让许愿团长停止许愿。
- **弹窗和提示框**：确认、输入、二选一弹窗和鼠标悬停提示都用插件自己的皮肤画，和窗口风格一致（物品提示仍是游戏自带的）。危险操作（清空、让出）的确定按钮是红色。
- **聊天节奏**：插件发的相邻两条聊天至少隔 0.3 秒，多行的宣言、播报不会乱序。
- **开始许愿**：
  - 这个团里还没人开过许愿（刚进新团，或记着的许愿团长不在团里）：先悄悄问一下团员手里有没有许愿数据（约 1.5 秒）。自己本地和团员手里都没有就直接开始；有就弹二选一："继续上次的许愿"或红色的"清空，重新开始"，弹窗写明本地和团员手里各有多少人许愿、最后更新时间。选"继续"时，团员的数据比自己的新就用团员的；选"清空"则全团的许愿和分数归零后开始。
  - 同一个团里继续（停止后再开始、换人接手、重载或崩溃后重登）：不弹窗，直接继续；本地是空的就悄悄从团员那里拿回来。
  - 离开团队（或登录时不在团队里）后，"这个团已开过许愿"的记录清除。
- **导出窗口**：右下角"复制"按钮会全选文字，再按 Ctrl+C 即复制（游戏不允许插件直接写剪贴板）。导入窗口没有"复制"，打开时自动定位到输入框，按 Ctrl+V 粘贴后点"导入"。
- **许愿页工具栏**（团长、助理）：开始/停止许愿、开团公告、宣言、通报未许愿、播报全部、搜索框。通报类按钮点后 2 秒内置灰，防止连点刷屏。底部是筛选标签"全部 / 已许愿 / 未许愿 / 重复"（各带人数，选中的高亮）；右键"未许愿"在团队频道通报未许愿名单。
- **设置 → 数据**：每项一行（左边名称和一行说明，右边按钮）：全团初始分数、导出许愿表、导入备份、从团员恢复、快照、自动快照开关；"清空许愿表"红色，单独放在"危险操作"下。设置页内容超出一屏时可用滚轮滚动。
- **备份码**："设置 → 数据 → 导出许愿表"（或 `/xy export`）显示可读的名单和一段备份码（以 `RWB2:` 开头、`:END` 结尾的乱码串，带校验值，手改任何一个字符都导入不了；这是防手改，不是加密），复制到游戏外保存（记事本、聊天软件都行），也可以按游戏截图键存成图片。"设置 → 数据 → 导入备份"（或 `/xy import`）把备份码粘贴回来，确认后替换当前的许愿表和掉落列表，许愿团长会同步给全团。备份码和可读文字一起粘贴也能识别；复制不完整时会提示。
- **退团清空**：离开团队时按设置"弹窗询问"（默认）或"直接清空"。

## 9. 界面

视觉和布局以 [界面效果图.html](界面效果图.html) 为准。

- 许愿列表的分数旁边，还有没拿到的许愿的人显示金色的"+5"（许愿加分：拍自己许愿的装备时最多可出 现有分数 + 5；出 5 分不扣分，出 6~9 分只扣超出 5 的部分）。鼠标移上去有说明。
- 小地图按钮、关于页和插件列表的图标都是插件自带的"许愿星"（`Images/MinimapButton.tga`，由 `tools/icon/make_icon.py` 生成）。

- 主窗口（宽约 600）：标题栏、状态行（灰"未开始" / 绿"许愿进行中" / 黄"已停止"，后接许愿团长名）、三个标签页（许愿、掉落与拍卖、设置）、底部状态栏（左侧计数，右侧同步状态）。Esc 关闭。
- 拍卖弹窗（宽约 300）：唯一的常驻浮动界面；可收成一行小条。没有拍卖时，团长、助理屏幕上只有"待拍 N"按钮（有待拍物品时才显示）。
- 两套皮肤：扁平暗色（默认）、暴雪原生，切换立即生效。
- 小地图按钮：左键开关主窗口，右键菜单，拖动沿小地图边缘移动。
- 右键团队成员：许愿助手 → 查询许愿；许愿团长另有增加 / 扣除 1~4 分。

## 10. 命令

| 命令 | 作用 |
|---|---|
| `/xy`、`/xyt` | 开关主窗口；`/xy help` 列出子命令 |
| `/xy export` | 导出许愿表（每行 `名字（职业）：许愿，剩余 N 分`）和备份码 |
| `/xy import` | 粘贴备份码恢复许愿表和掉落列表 |
| `/xy rl` | 重置所有窗口和小地图按钮位置 |
| `/xy backup` / `restore` / `autobackup on\|off` | 快照 |
| `/xypm`、`/拍装备` | 拍第一件待拍物品；`/xypm reset` 重置拍卖窗口位置 |
| 密语 `cxxy` | 查询自己的许愿和分数 |

## 11. 技术约定

- 插件消息前缀 `RaidWish`，协议版本 2；格式 `版本\t命令\t字段…`，超过 255 字节自动分片。收到更高版本的消息时提示一次"团里有人使用了更新版本的许愿助手"。
- 存档：`RaidWishDB`（账号级，带 `schema` 版本号）、`RaidWishCharDB`（角色级：窗口位置、缩放、小地图位置）。
- 内部事件一律以 `RW_` 开头。
- 首领战等聊天锁定期间：读到保密值的聊天直接忽略；要发的聊天和插件消息先排队，解除后补发（过期的倒数等消息丢弃）。
- 开发与测试方法见 [开发工具.md](开发工具.md)。
